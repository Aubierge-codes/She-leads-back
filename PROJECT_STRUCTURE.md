# Project Structure

Short description of what each folder and file does.

## Root

- `prisma.config.ts` — Prisma 7 config: schema location, migrations path, seed command, DB connection URL.
- `.env` — Environment variables (git-ignored). `.env.example` documents every variable; see `docs/OPERATIONS_GUIDE.md`.
- `nest-cli.json` — NestJS CLI configuration (build/compile settings).
- `tsconfig.json` / `tsconfig.build.json` — TypeScript compiler settings; build config excludes tests and the unrelated `frontend/` folder.
- `package.json` — Dependencies and npm scripts (`start:dev`, `build`, `test`, etc).
- `frontend/` — A separate Next.js app living alongside the backend; not part of this NestJS API.

## `prisma/`

- `schema.prisma` — The full data model: `User`, `Community`, `School`, `Participant`, `CleanupEvent`, `CleanupAttendance`, `WasteRecord`, `InventoryItem`, `InventoryTransaction`, `EnvironmentalClub`, `WeeklyReport`, `Donor`, `Donation`, `NewsletterSubscriber`, `PartnershipInquiry`, plus enums.
- `seed.ts` — Creates the first admin (`SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`). Safe to run on every deploy: it never overwrites an existing admin's password unless `SEED_ADMIN_PASSWORD` is set explicitly. In production it requires that variable to create the first admin.

## `generated/prisma/`

Auto-generated Prisma Client code (do not edit). Regenerated by `npx prisma generate`.

## `src/main.ts`

App entrypoint: production safety check for `JWT_SECRET`, CORS allow-list from `FRONTEND_URL`, optional proxy trust (`TRUST_PROXY`), global validation pipe (`class-validator`), and Swagger UI at `/api` (hidden in production unless `ENABLE_SWAGGER=true`).

## `src/app.module.ts`

Root module: wires up global config, Prisma, and every feature module; registers the global JWT auth guard and roles guard.

## `src/app.controller.ts` / `app.service.ts`

Trivial public health-check route (`GET /`).

## `src/prisma/` — Database connection

- `prisma.service.ts` — Wraps `PrismaClient` as an injectable NestJS provider; connects to Postgres via the `@prisma/adapter-pg` driver adapter using `DATABASE_URL`.
- `prisma.module.ts` — Global module exporting `PrismaService` so any module can inject it without re-importing.

## `src/common/` — Shared building blocks

- `decorators/public.decorator.ts` — `@Public()` marks a route as not requiring a JWT (used on login, health check).
- `decorators/roles.decorator.ts` — `@Roles(Role.ADMIN, ...)` restricts a route to specific user roles.
- `decorators/current-user.decorator.ts` — `@CurrentUser()` pulls the authenticated user off the request.
- `guards/roles.guard.ts` — Enforces `@Roles()` metadata; allows the request through if no roles are required.

## `src/auth/` — Login & JWT

- `auth.module.ts` — Registers Passport, JWT module (reads secret/expiry from config), and the strategy.
- `auth.service.ts` — Validates email/password (bcrypt compare) and issues a signed JWT.
- `auth.controller.ts` — `POST /auth/login` (public, rate-limited) and `PATCH /auth/password` (change your own password).
- `dto/login.dto.ts`, `dto/change-password.dto.ts` — Validate login and password-change input.
- `strategies/jwt.strategy.ts` — Verifies incoming bearer tokens and loads the corresponding user.
- `guards/jwt-auth.guard.ts` — Global guard applied to every route; skips routes marked `@Public()`.

## `src/users/` — Admin user management (Admin-only)

- `users.service.ts` — CRUD for users; hashes passwords with bcrypt; strips password before returning a user.
- `users.controller.ts` — `POST/GET/PATCH/DELETE /users` (restricted to `Role.ADMIN`).
- `dto/create-user.dto.ts`, `dto/update-user.dto.ts` — Input validation for creating/updating users.

## `src/communities/` — Community records

- `communities.service.ts` / `communities.controller.ts` — CRUD for communities (name, state, notes), with nested schools/participants on lookup.
- `dto/*.dto.ts` — Create/update validation.

## `src/schools/` — School records

- `schools.service.ts` / `schools.controller.ts` — CRUD for schools (name, location, teacher coordinator, linked community).
- `dto/*.dto.ts` — Create/update validation.

## `src/participants/` — Program participants

- `participants.service.ts` / `participants.controller.ts` — CRUD for participants (name, age, school, community, status).
- `dto/*.dto.ts` — Create/update validation.

## `src/cleanup/` — Cleanup events, attendance, waste tracking

- `cleanup.service.ts` — CRUD for events; bulk attendance marking (upsert); adding/listing waste records per event.
- `cleanup.controller.ts` — `/cleanup/events` CRUD, `POST /:id/attendance`, `POST`/`GET /:id/waste-records`.
- `dto/create-cleanup-event.dto.ts`, `update-cleanup-event.dto.ts` — Event validation.
- `dto/mark-attendance.dto.ts` — List of participant IDs + attended flag.
- `dto/create-waste-record.dto.ts` — Waste type, weight (kg), bag count.

## `src/inventory/` — Equipment & materials

- `inventory.service.ts` — CRUD for items; `recordTransaction` applies RESTOCK/USAGE/ADJUSTMENT to quantity inside a DB transaction; `listLowStock` filters items at/below their minimum stock.
- `inventory.controller.ts` — Item CRUD, `GET /inventory/low-stock`, `POST /:id/transactions`.
- `dto/create-inventory-item.dto.ts`, `update-inventory-item.dto.ts` — Item validation.
- `dto/create-inventory-transaction.dto.ts` — Transaction type + quantity + optional note.

## `src/clubs/` — Environmental clubs

- `clubs.service.ts` / `clubs.controller.ts` — CRUD for clubs (school, president, meeting frequency, member count).
- `dto/*.dto.ts` — Create/update validation.

## `src/reports/` — Weekly activity reports

- `reports.service.ts` — CRUD for reports; separate `updateStatus` method for the approval workflow (DRAFT → SUBMITTED → APPROVED/REJECTED).
- `reports.controller.ts` — Report CRUD plus `PATCH /:id/status`.
- `dto/create-report.dto.ts`, `update-report.dto.ts` — Week number, year, activities text, photo URLs, school.
- `dto/update-report-status.dto.ts` — Just the new status.

## `src/analytics/` — Chart-ready aggregations

- `analytics.service.ts` — Grouped counts/sums for waste by type, participants by status, cleanup events by status, inventory transactions by type, reports by status.
- `analytics.controller.ts` — One `GET` endpoint per aggregation, under `/analytics`.

## `src/dashboard/` — Top-level impact summary

- `dashboard.service.ts` — Single `summary()` combining totals across every module (participant/school/community/event/club counts, pending reports, total waste weight/bags, low-stock count).
- `dashboard.controller.ts` — `GET /dashboard/summary`.

## `src/public/` — Data for the public website

- `public.controller.ts` — Open (no login) read-only routes: `GET /public/summary`, `/public/reach`, `/public/impact`.
- `public.service.ts` — Returns only non-sensitive, trimmed fields so the public site can never expose staff-only data.

## `src/newsletter/` — Newsletter signups

- `POST /newsletter` (public, idempotent) stores an email; `GET /newsletter` (login) lists subscribers.

## `src/partnerships/` — "Become a Partner" inquiries

- `POST /partnerships` (public) stores an inquiry; `GET`, `GET /:id` and `PATCH /:id/status` (login) let staff triage it (NEW / CONTACTED / CLOSED).

## `src/donations/` — Donation pledges

- `POST /donations` (public) records a pledge as PENDING (no payment is processed); staff routes list, show stats, and update status.

## `scripts/smoke-test.mjs`

Repeatable 64-check test of a running API: public vs protected routes, roles, password change, removed-user lockout, soft deletes.

## `docs/`

- `OPERATIONS_GUIDE.md` (and `.pdf`) — go-live checklist, configuration, deployment, security model, staff guide, API reference, troubleshooting.
